# PRD 작성 실습 워크시트 기반 — 상세 PRD

> PRD v1.0 (2026-07-20) — 기존 짧은 초안(문제/목표/사용자/핵심기능/성공지표 5항목)을 워크시트 양식에 맞춰 상세화한 버전입니다.
> 자료 조사가 필요한 수치는 실제로 검색·확인된 값만 기재했고, 확인하지 못한 항목은 "검증 필요"로 표기했습니다(추측·추정치로 채우지 않음).

---

### 제품/기능명

```
리딩방 추천종목 교차검증 필터링 MVP — "건전 투자 유도형" 투자자 보호 도구
```

---

### 1. TL;DR — 가치 정의

| 구성 요소 | 내용 |
| --- | --- |
| **누가** | 텔레그램 등 SNS 투자 리딩방에서 "무료 종목 리딩"을 받는 개인 투자자, 특히 급등주·소형주·바이오주 추천에 쉽게 휩쓸리는 투자 지식이 낮은 투자자 |
| **왜** (해결할 문제) | 리딩방 세력이 소액으로 저유동성 소형주를 매수세로 띄운 뒤, 소규모 인터넷 언론사에 보도자료성 기사를 뿌려 "진짜 호재"처럼 포장해도, 일반 투자자는 이를 스스로 판별할 근거가 없는 문제 |
| **어떻게** (제품 사용 방법) | 리딩방 메시지 크롤링 → KRX 전체 종목 사전 기반 추천 종목 추출 → 언론사 신뢰도·뉴스 근접중복(버스트) 탐지 → 뉴스-공시 매칭 → 기업 건전성(DART) 스코어링 → 거래량 급등 탐지를 교차검증해, 설명 가능한 규칙으로 "투자 주의" / "정상 호재 가능성" / "특이사항 없음"을 판정 |
| **어떤 가치** | 실제 급등이 벌어지기 전에 경고 신호를 확인함으로써 "묻지마 추종매수"를 피하고, 왜 위험한지 근거를 직접 확인할 수 있는 설명 가능성 확보 |

**TL;DR 한 문장:**
```
텔레그램 리딩방에서 무료 종목 추천을 받는 개인 투자자가, 추천 종목이 실제 호재인지 세력의 작전인지 스스로 판별할 근거가 없는 문제를 해결하기 위해 —
종목 추출, 언론사 신뢰도 분류, 뉴스-공시 상관관계, 기업 건전성, 거래량 급등을 교차검증하고 설명 가능한 규칙으로 판정하는
건전 투자 유도형 필터링 MVP를 개발한다. 통계적 이상치 탐지(Isolation Forest)는 규칙이 놓칠 수 있는 패턴을 추가로 훑어보는
보조 신호로만 사용하며, "실제로 투자자를 더 잘 보호하는 도구를 만드는 것"이 방법론 선택의 최우선 기준이다.
```

> 체크: 기능 이름이 아니라 사용자의 문제와 가치가 드러나는가? — 네. 기능 나열이 아니라 "판별 근거 없음"이라는 사용자 문제에서 출발합니다.

### 3. Problem Statement — 문제 정의

| # | 왜? | 답변 |
| --- | --- | --- |
| 1 | 사용자는 왜 이 상황에서 불편/불안을 느끼는가? | 리딩방에서 "무료 종목 리딩"을 받아도, 그 종목이 실제 호재가 있는 기업인지 세력이 소액으로 만들어낸 "숫자놀음"인지 판별할 근거가 없다. |
| 2 | 왜 기존 대안으로는 해결이 안 되는가? | 재무 스크리너(밸류라인 등)는 사후 재무지표만 제공하고, KRX KIND의 투자주의환기종목은 이상 급등이 이미 벌어진 뒤 사후 지정된다. 언론 보도조차 소규모 인터넷 언론사에 보도자료성 기사를 게재하는 방식으로 조작될 수 있어 신뢰하기 어렵다. |
| 3 | 왜 이 문제가 단순 정보 제공이 아닌 제품(파이프라인) 기회인가? | 비정형 리딩방 메시지에서 종목을 추출하고, 뉴스·공시·재무·거래량을 실시간으로 교차검증하는 작업은 사람이 수작업으로 하기 어렵다. 여러 공공 API를 자동으로 연동·판정하는 파이프라인이 필요하다. |
| 4 | 왜 이 문제가 지금 해결되어야 하는가? | 개인 투자자 저변이 활동계좌 1억 877만 개로 계속 확대되는 가운데, 리딩방 피해 규모가 2년간 1조 2,901억 원에 이를 만큼 지속적으로 발생하고 있다. |
| 5 | 왜 우리가 이 문제를 해결하기 적합한가? | Open DART, KRX(FinanceDataReader), 네이버 뉴스 검색 등 공공·오픈 API만으로 실데이터 기반 MVP를 무료로 구현할 수 있고, "설명 가능한 규칙이 메인, 통계적 이상치 탐지는 보조 교차검증"이라는 설계 원칙 덕분에 판정 근거를 사람이 즉시 검증할 수 있다. |

**3단 구조 정리**

| 단계 | 질문 | 내용 |
| --- | --- | --- |
| **Current Situation** | 사용자가 현재 어떤 상황에 놓여 있는가 | 개인 투자자가 텔레그램 등 공개 리딩방에 초대되어 특정 종목의 "무료 리딩"(추천)을 받는다. |
| **Pain Point** | 그 상황에서 어떤 불편/불안을 겪는가 | 추천 종목이 저유동성 소형주·바이오주인 경우가 많아 소액 매수세만으로도 급등할 수 있고, 함께 뿌려지는 뉴스 기사가 진짜 호재 보도인지 조작된 보도자료인지 구분할 수 없다. |
| **Impact** | 이 문제가 어떤 부정적 결과를 만드는가 | "묻지마 추종매수" 후 세력의 물량 떠넘기기에 노출되어 손실을 볼 수 있다. 실제로 2년간(2023.9~2025.9) 약 1조 2,901억 원의 피해가 발생했다(아시아타임즈). |

### 7. Key Scenario

```
① Context
김건우는 지인이 초대한 텔레그램 오픈채팅 리딩방에서 "이번 주 강력 추천 종목"이라는 메시지를 받는다. 함께 첨부된 뉴스
링크에는 해당 기업의 "대규모 수주 계약" 기사가 걸려 있다.

② Problem Moment
종목명은 처음 들어보는 소형주이고, 뉴스 기사를 낸 언론사도 낯설다. 이 정보를 믿고 매수해도 되는지 판단할 방법이 없다.

③ Product Interaction
리딩방 메시지와 종목명을 필터링 파이프라인에 입력하면, ① 해당 종목이 최근 며칠간 이 채널을 포함한 여러 채널에서
집중적으로 언급됐는지, ② 함께 뿌려진 뉴스가 KPF 참여 언론사 등 신뢰할 수 있는 매체에서 나온 것인지, ③ 뉴스 내용과
일치하는 실제 DART 공시가 있는지, ④ 기업의 부채비율·감사의견·최대주주 지분변동에 이상 신호가 없는지, ⑤ 최근
거래량이 평소 대비 비정상적으로 급등했는지를 각각 확인해 규칙 기반으로 결합한다.

④ Resolution
파이프라인은 "낯선 소형 매체발 기사 + 공시 미확인 + 거래량 급등 없음" 조합을 근거로 "투자 주의" 판정과 함께, 어떤
신호가 왜 의심스러운지 근거를 함께 출력한다. Isolation Forest 기반 통계적 이상치 점수도 보조 신호로 함께 표시된다.

⑤ Outcome
김건우는 "왜 위험한지" 근거를 직접 확인하고, 검증되지 않은 추천을 그대로 따라 매수하지 않기로 결정한다.
```

### 9. Scope

**In Scope (MoSCoW)**

| 분류 | 기능 | 이유 |
| --- | --- | --- |
| **Must-have** | 텔레그램 공개 리딩방 크롤링(Telethon 비동기, 스노우볼 채널 확장) | 원천 데이터 없이는 파이프라인 자체가 성립하지 않음. |
| **Must-have** | KRX 전체 상장 종목 사전 기반 추천 종목 추출(경계 인식 매칭으로 오탐 방지) | P0 스토리 직접 해결. 종목 추출 정확도가 이후 모든 단계의 전제. |
| **Must-have** | 언론사 신뢰도 스코어링(KPF 참여 언론사 화이트리스트 기반) | P0 스토리 직접 해결. "기사만 뿌리면 호재로 보이는" 문제의 핵심 대응. |
| **Must-have** | 뉴스-공시 상관관계 확인(Open DART 공시검색, 우선주 대응 포함) | P0 스토리 직접 해결. 진짜 호재와 숫자놀음을 구분하는 핵심 신호. |
| **Must-have** | 설명 가능한 규칙 기반 최종 판정(취약도 가중 동적 임계값) | P0 스토리 직접 해결. 방법론 원칙("설명 가능한 규칙이 메인")의 핵심 구현. |
| **Should-have** | 기업 건전성 스코어링(부채비율·감사의견·최대주주 지분변동·관리종목 이력) | P1 스토리 연결. 판정의 근거를 더 두텁게 함. |
| **Should-have** | 거래량 급등 탐지(FinanceDataReader 실시세) | P1 스토리 연결. |
| **Should-have** | 뉴스 근접중복(버스트) 탐지(MinHash) | 여러 매체가 짧은 기간에 거의 동일한 문구를 반복 게시하는 조작 의심 패턴 탐지. |
| **Could-have** | 통계적 이상치 탐지(Isolation Forest) 보조 교차검증 | P2 스토리 연결. 규칙이 놓칠 수 있는 패턴을 추가로 훑어보는 보조 신호. 표본 5개 미만일 때는 비활성화. |
| **Could-have** | 결과 CSV/XLSX 저장 및 다운로드 | 실행 결과를 재검토·공유하기 위한 편의 기능. |

**Out of Scope**

| 제외 기능 | 제외 이유 |
| --- | --- |
| 실시간 자동매매/주문 실행 | 투자자문업·투자매매업 라이선스가 필요한 영역으로, 본 프로젝트는 "정보 제공/경고" 도구이지 투자 조언·매매 실행 도구가 아님. |

| 실사용자 대상 상용 서비스화(과금, 회원 관리 등) | 현재는 인턴십 학습/검증용 프로토타입 단계이며 상용화 계획은 본 PRD 범위 밖. |

### 10. Constraints & Assumptions

**제약 (바꿀 수 없는 한계)**

| 영역 | 제약 내용 |
| --- | --- |
| 데이터 | 텔레그램은 공개 채널만 크롤링 대상으로 한정. Open DART는 corp_code가 종목(우선주 등)이 아닌 법인 단위로 관리되어 별도 매핑이 필요. |
| API | Open DART·네이버 뉴스 검색 API는 호출 한도(rate limit)가 있어 대량 종목 동시 조회 시 지연·실패 가능성 있음 (`TOP_N_STOCKS_FOR_ANALYSIS` 상한으로 완화 중). |
| 법무 | 투자자문업 등록 없이 확정적 매수/매도 추천을 제공할 수 없음 — 판정 결과는 참고용 경고 신호로 한정해야 함. 텔레그램 공개 채널 데이터 수집의 개인정보 처리 범위는 법무 검토가 이루어지지 않음. |
| 자원 | Google Colab 무료 티어 기준 실행을 전제로 하며, 대규모 상시 크롤링·서버 운영은 범위 밖. |
| 데이터 신뢰도 | 언론사 신뢰도 화이트리스트 중 `OTHER_MAJOR_MEDIA`(보완 매체 목록)는 공신력 있는 공식 출처가 아닌 자체 큐레이션이라는 한계를 프로젝트 내부적으로 이미 인지하고 있음. |

**가정 (검증해야 할 전제)**

| 가정 | 검증 방법 |
| --- | --- |
| 리딩방에서 집중 언급되는 저유동성 소형주가 실제 거래량 급등으로 이어지는 경우가 유의미하게 존재한다 | 실데이터 파일럿 실행 후 `mention_summary`와 실제 거래량 급등 이력을 대조 (검증 필요) |
| 낯선 소형 매체 보도 + 공시 미확인 조합이 실제 "숫자놀음" 사례와 상관관계가 있다 | 규칙 기반 판정 결과를 실제 언론에 보도된 리딩방 사기 사건(예: 210억 편취 사건)과 사후 대조 (검증 필요) |
| 규칙 기반 임계값(`pump_threshold = 0.5 - 0.2*취약도`)이 실제 사건 데이터에서도 유효하다 | 백테스트용 실제 사건 데이터셋 확보 후 검증 필요 — 현재 미실시 |
| 실사용자가 경고 근거를 보고 실제로 추종매수를 자제하는 행동 변화를 보인다 | 실사용자 파일럿(설문/행동 로그) 필요 — 현재 미실시 |
