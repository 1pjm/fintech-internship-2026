# 전세탐정 — 위험 모니터링 대시보드 (59회차 실습)

`전세사기예측_AUC 비교.ipynb`로 이미 학습해 둔 LightGBM 모델(`dashboard/model/`)을 재학습 없이
가져다 쓰는 **트랙 A** 실습. 설계 근거는 [`59회차_실습_워크시트_작성본.md`](59회차_실습_워크시트_작성본.md)에,
구현 순서는 짝 문서 `59회차_대시보드_구현_가이드.md`에 그대로 따랐다.

## 구성

| 파일 | 역할 |
|---|---|
| `common.py` | 경로·등급 컷오프·체크규칙(RULES)·색·점수 재분류 함수. 02·03·04가 공유 |
| `02_전처리.py` | `../data/전세보증대위변제현황_깡통라벨.xlsx` → `data/clean.parquet` |
| `03_스코어링.py` | `dashboard/model/`의 학습된 모델로 위험도점수(0~100)를 매겨 `data/scored.parquet` 저장 |
| `04_시각화.py` | Streamlit 화면. **새 계산 없이** 03 결과만 읽고, 등급 컷오프·체크 기준만 화면에서 재분류 |
| `data/` | `clean.parquet`, `scored.parquet` (02·03 실행 결과, 재현 가능하도록 커밋해 둠) |

## 실행

```bash
cd 59_전세탐정_dashboard
pip install -r requirements.txt

# 1) 전처리 (원본이 안 바뀌었으면 생략 가능 — data/clean.parquet 이미 있음)
python 02_전처리.py

# 2) 스코어링 — dashboard/model/의 학습된 모델을 그대로 사용 (재학습 아님)
python 03_스코어링.py

# 3) 대시보드 실행
streamlit run 04_시각화.py
```

`python 04_시각화.py`로 실행하면 화면이 뜨지 않는다 — 반드시 `streamlit run`으로 실행한다.

## 핵심 설계 결정 (워크시트 요약)

- **정규화**: `minmax`가 아니라 "기준 대비 점수" — 모델 확률(0~1)을 100점으로 스케일하고,
  고정 임계값(주의 30 / 위험 80)으로 등급을 나눈다. 80은 임의의 숫자가 아니라 코드 파일
  (`전세사기예측_AUC 비교.ipynb`)에서 F1이 최대가 되는 임계값(`best_t=0.80`)이다.
- **Gate**: 거래량(시도×주택유형×월 그룹의 실거래 표본 수) < 100이면 그룹 통계 자체가
  불안정하다고 보고 "판단보류"로 뺀다 (전체 50,054건 중 88건).
- **체크리스트 규칙**: 가중합 대신 LightGBM이 학습한 비선형 조합을 쓰되, SHAP 전역 중요도
  상위 4개(깡통지수·선순위채권비율·갱신요구권행사비율·전세가율)를 "무엇부터 확인하나" 체크리스트로
  노출한다. 사이드바에서 개별 기준을 조정할 수 있다.
- **04는 새로운 계산을 하지 않는다**: 사이드바 슬라이더는 이미 계산된 위험도점수를 다른 컷오프로
  재분류할 뿐, 모델을 다시 돌리지 않는다.

## 한계

- 이 저장소의 `dashboard/model/`을 그대로 재사용하므로, 그 모델의 한계(합성데이터 기반, 라벨은
  "미반환 사고"지 "사기 판정"이 아님 등)를 그대로 물려받는다.
- 체크리스트 규칙의 "가중치(%)"는 실제 가중합에 쓰이는 값이 아니라 SHAP 기여도를 참고용으로
  표시한 것이다 — 모델 점수 자체는 39개 피처의 비선형 조합에서 나온다.
