### 자가 진단 — 빈칸 채우기

```python
fig, ax = plt.subplots(figsize=(10, 4))       # ① Figure와 Axes를 한 번에
ax.plot(df["일시"], df["실패율"], label="실패율")
ax.axhline(3.0, color="red", linestyle="--")  # ② 임계선 3.0%
ax.legend()                                    # ③ 범례 켜기
ax.spines[["top", "right"]].set_visible(False)
st.pyplot(fig)                                  # ④ 화면에 올리기
plt.close(fig)                                  # ⑤ 메모리 정리
```

## 1-3. Streamlit 필수 용어

### 실행 모델 — 이것만은 반드시

> **위젯을 건드릴 때마다 `.py` 파일이 맨 위부터 아래까지 다시 실행된다.**

이 한 줄에서 나머지가 전부 따라 나옵니다.

| 그래서 생기는 일 | 대응 |
|---|---|
| 일반 변수는 매번 초기화된다 | 유지하려면 `st.session_state` |
| 파일 읽기가 매번 반복된다 | `@st.cache_data` 로 감싼다 |
| 위쪽 코드가 아래쪽 결과를 좌우한다 | 필터 → 계산 → 표시 순서를 지킨다 |
| 조건이 안 맞는데 아래가 계속 실행된다 | `st.stop()` 으로 끊는다 |

### 기능별 정리

| 갈래 | 함수 | 언제 |
|---|---|---|
| **페이지** | `st.set_page_config(page_title, page_icon, layout="wide")` | **맨 처음 st 명령이어야 한다** |
| **레이아웃** | `st.sidebar` · `st.columns` · `st.tabs` · `st.expander` · `st.divider` | 사이드바=조작, 본문=결과 |
| **텍스트** | `st.title` · `st.subheader` · `st.markdown` · `st.caption` · `st.code` | `caption`은 출처·갱신시각 자리 |
| **숫자 카드** | `st.metric(label, value, delta)` | KPI 한 줄. `delta`로 비교 맥락을 준다 |
| **표** | `st.dataframe(df, column_config=..., hide_index=True)` | `ProgressColumn`, `NumberColumn(format=)` |
| **그림** | `st.pyplot(fig)` → `plt.close(fig)` | 부록 차트를 그대로 올리는 통로 |
| **알림** | `st.error` · `st.warning` · `st.info` · `st.success` | 심각도 색을 코드로 고정 |
| **입력 위젯** | `slider` · `select_slider` · `multiselect` · `selectbox` · `checkbox` · `date_input` | 반환값이 곧 필터 값 |
| **내보내기** | `st.download_button(..., encoding="utf-8-sig")` | 엑셀 한글 깨짐 방지 |
| **상태** | `st.session_state` | 버튼 누적, 여러 rerun에 걸친 값 |
| **캐시** | `@st.cache_data`(데이터) · `@st.cache_resource`(연결·모델) | 입력이 같으면 결과가 같은 것에만 |
| **흐름** | `st.stop()` | 선택이 비었을 때 아래를 막는다 |
| **실행** | `streamlit run 04_시각화.py` | `python`으로 실행하면 화면이 안 뜬다 |

# STEP 2. 02 전처리 설계 (33회차 흐름 그대로)

트랙 B는 여기서 새로 설계하고, 트랙 A는 **이미 짠 코드가 어느 단계에 해당하는지 적기만** 하면 됩니다.

| 단계 | 무엇을 확인·처리하나 | *예시(D 결제)* | 내 설계 |
|---|---|---|---|
| 1 불러오기·규격 | 필수 열이 다 있나 | *`encoding="utf-8-sig"`, 필수 8열 확인* | `openpyxl`로 xlsx 로드, 21개 컬럼 존재 확인 |
| 2 결측 | 어느 열이, 왜 비었나 | *`비고`만 빔 → MNAR → `""` 로 보존* | 결측 0건 — 처리 불필요 |
| 3 중복 | 시스템 키 / **업무 키** | *업무 키 = `일시`+`PG사` → 0건* | 업무 키 = `일련번호`(이미 고유) → 중복 0건 |
| 4 도메인 규칙 | 업무적으로 불가능한 값 | *`성공+실패 = 시도`, 음수 금액* | 금액·비율 컬럼 음수 없음 확인, 깡통전세여부(중복 파생 라벨)는 드롭 |
| 5 변환 | 날짜형·범주 정리 | *`to_datetime`, `일자`·`시간대` 파생* | `보증완료월` → `보증완료연도`/`보증완료월`(정수)로 분리, `시도`/`주택구분` → category |
| 6 파생변수 | 비교 가능한 **비율** | *`실패율`, `금액실패비중` (분모 0 방어)* | `선순위채권비율 = 선순위채권금액/주택가액`(분모 0 방어), `위험도점수 = model.predict_proba × 100` |
| 7 이상치 | IQR·도메인 → **보존 + 표시** | *IQR 상한 2.77% 초과 8행에 플래그* | 클리핑하지 않고 원본 값 그대로 둔다 — 이미 학습된 모델(`dashboard/train_model.py`)도 원본 값으로 학습했고, 트리 기반이라 극단값에 강건함이 이전 리포트에서 검증됨. 단, 거래량은 03의 Gate 판정 신호라 더더욱 건드리면 안 됨 |
| 8 검증·저장 | 눈으로 확인 후 parquet | *행수·기간·결측 0 확인* | 행수(50,054) · 기간(2022~2024) · 결측 0 확인 후 `clean.parquet` 저장 |

**내 데이터의 업무 키**: 일련번호　**분모가 0이 될 수 있는 비율**: 선순위채권비율(주택가액), 시세대비보증금비율(시세_평균전세보증금)

# STEP 3. 03 스코어링 설계 (40·41회차 공식 그대로)

```text
FinalScore = Gate × ( w1×점수1 + w2×점수2 + w3×점수3 )
```

> **트랙 A 특이사항**: 우리는 규칙을 손으로 설계하는 대신, 이미 학습된 LightGBM 모델
> (`전세사기예측_AUC 비교.ipynb`, scale_pos_weight로 불균형 보정, ROC-AUC 0.887)의
> 예측 확률을 그대로 `위험도점수`로 쓴다. 아래 표는 이 확률 점수를 40·41회차 프레임에
> 맞춰 다시 설명한 것이다 — **가중합(Σw×점수) 대신 모델이 학습한 39개 피처의 비선형
> 조합**을 쓰고, SHAP 기여도로 "사실상의 가중치"를 사후에 보여준다.

## 3-1. ① 정규화 — 어떤 방식을 쓸 것인가

| 방법 | 언제 | 내 선택 |
|---|---|---|
| `minmax` (0~100) | 상대 비교·랭킹 | ☐ |
| **기준 대비 점수** (기준=50점) | **정책 기준선이 있을 때 = 모니터링** | ☑ |
| 구간 점수(Band) | 정책상 구간이 딱 정해져 있을 때 | ☐ |

> 모니터링에서 `minmax`를 쓰면 **오늘 가장 나쁜 값이 항상 100점**이 됩니다.
> 내일 최댓값이 달라지면 같은 실패율에 다른 점수가 나와 어제와 비교할 수 없습니다.

**내 선택 근거**: 모델 확률(0~1)을 100점 만점으로 스케일한 뒤, 0.30 / 0.80이라는 고정 정책 임계값(F1 최적값
기준)으로 등급을 나누므로 "기준 대비 점수" 방식에 해당한다. 같은 입력이면 오늘도 내일도 같은 점수가
나오기 때문에 `minmax`처럼 기준이 매번 흔들리는 문제가 없다.

## 3-2. ② Gate — 아예 판단에서 빼는 조건

| 항목 | *예시* | 내 설계 |
|---|---|---|
| Gate 조건 | *시도건수 ≥ 100* | 거래량(해당 시도×주택유형×월 그룹의 실거래 표본 수) ≥ 100 |
| 왜 필요한가 | *20건 중 1건 실패 = 5%. 비율이 튄다* | 표본이 100건 미만이면 시세_평균전세보증금 등 그룹 통계 자체가 불안정해서, 모델 입력값의 신뢰도가 낮아진다 |
| 통과 / 보류 건수 | *2,109 / 51* | 49,966 / 88 |
| 보류 행의 등급 이름 | *`판단보류`* | `판단보류` |

> **Gate는 반드시 곱셈**입니다. 다른 점수가 아무리 높아도 Gate가 0이면 최종 0이어야 합니다.
> 그리고 보류를 `정상`이라고 부르면 안 됩니다. **"모른다"와 "괜찮다"는 다른 말입니다.**

## 3-3. ③ 가중합 — 규칙과 가중치

> 아래는 실제 가중합 공식이 아니라, **모델이 학습한 SHAP 전역 중요도 상위 항목**을 "체크리스트용
> 규칙"으로 다시 뽑은 것이다. 대시보드의 "무엇부터 확인하나" 절에 그대로 쓰인다(합계가 100%가
> 아닌 이유: 나머지는 39개 피처에 걸쳐 얇게 분산돼 있다).

| 규칙 이름 | 검사하는 열 | 기준 | 가중치(SHAP 기준) | 이 규칙이 뜨면 무엇부터 보나 |
|---|---|---|---|---|
| 깡통지수 과다 | 깡통지수 | ≥ 0.8 | 32% | 등기부등본 근저당권·선순위채권 설정 확인 |
| 선순위채권 과다 | 선순위채권금액 ÷ 주택가액 | ≥ 0.10 | 15% | 선순위채권 설정 여부 확인 |
| 갱신요구권 저조 | 갱신요구권행사비율 | ≤ 0.10 | 6% | 임대인의 과거 세입자 교체 이력 확인 |
| 전세가율 과다 | 전세가율 | ≥ 0.90 | 4% | 시세 대비 보증금 직접 재계산 |
| | | **합계** | **57% (나머지 43%는 시도·주택유형 등 35개 피처에 분산)** | |

> 가중치는 숫자가 아니라 **운영 정책의 표현**입니다. "무엇을 더 중요하게 볼 것인가"를 적는 칸입니다.

## 3-4. ④ 검증 — 정답과 대조

정답 라벨이 있다면(`비고`, `is_fraud`, `이탈여부` 등) **점수 계산에 쓰지 않고** 검증에만 씁니다.

| 항목 | *예시* | 내 결과 |
|---|---|---|
| 정답 라벨 열 | *`비고 == "장애"`* | `대위변제여부 == 1` |
| 정답 쪽 평균 점수 | *94.4점* | 77.8점 |
| 나머지 평균 점수 | *19.1점* | 20.6점 |
| 두 집단이 겹치는가 | *정상 최고 39.2 < 장애 최저 92.5 → 안 겹침* | 정상 최고 98.5점 > 사고 최저 0.3점 → **일부 겹침**. 규칙 기반 장난감 예제와 달리 실제 ML 확률(ROC-AUC 0.887)이라 완전히 분리되진 않는다 — 이게 오히려 정직한 결과다 |

정답 라벨이 없다면: ☐ 상위 20건을 직접 눈으로 확인하고 "말이 되는가"를 적는다.

## 3-5. ⑤ 등급 → 액션 → Reason Code

**점수는 숫자로 끝나면 안 되고 행동으로 이어져야 합니다.**

| 점수 구간 | 등급 | 액션(누가 무엇을) | 내 데이터 건수 |
|---|---|---|---|
| Gate 미통과 | 판단보류 | 그룹 표본 부족 — 개별 실거래가·등기부 직접 확인 | 88 |
| 0 ~ 29 | 안전 | 정기 모니터링만 | 34,934 |
| 30 ~ 79 | 주의 | 등기부 선순위채권·주변 시세 재확인 권고 | 11,267 |
| 80 ~ 100 | 위험 | 보증보험(HUG) 가입 여부·선순위채권 우선 확인, 현장 확인 우선순위 상향 | 3,765 |

**Reason Code 문장 예시 3개** (경보 목록의 `사유` 열에 그대로 들어갑니다)
